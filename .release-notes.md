## MWORKS AI for DeepSeek Harness — v1.0.0

First public release. `dsh-mworks-ai` plugs the official MWORKS tooling into DeepSeek Harness so the agent can drive Syslab (Julia) and Sysplorer (Modelica) the same way the official Syslab AI and Sysplorer AI assistants do.

### What's inside

- **MCP servers** — `mcp__mworks_syslab__*` (8 tools: Julia execution, environment detection, help search, MATLAB→Julia mapping) and `mcp__mworks_sysplorer__*` (15 tools: session, library, model, check, translate, simulate, layout, results, plotting, API/model docs, resources).
- **`mworks_environment` tool** — reports the MWORKS installation it found: Syslab and Sysplorer roots, versions, the Julia runtime and the MCP entry points.
- **Official working rules** — Syslab requires `read_syslab_skill` → `detect_syslab_toolboxes` before any code execution; prefer `Ty*` packages; confirm APIs from local help; call `session_manager` before other Sysplorer tools; never write modeling outputs into the installation directories.
- **UI** — a *Runtime environment* section on this bundle's own page under **Plugins**: detected installations and versions, the Julia runtime, both MCP servers with path status, and the MWORKS skills the session can call, plus a **Re-detect** button. Nothing is added to the conversation.

### Install

```bash
npm install --save-dev dsh-mworks-ai
```

### Requirements

- A local MWORKS installation. `cordis.patch.yml` is written for Syslab `E:\MWORKS\Syslab 2026b`, Sysplorer `E:\MWORKS\Sysplorer 2026b` and Julia `C:\Users\Public\TongYuan\julia-1.10.10`; edit it if MWORKS lives elsewhere. The Runtime environment section and `mworks_environment` report what is actually found.
- The MWORKS skills you want the agent to follow, installed into a skill root the harness scans.

### Checks

`npm test` runs the three dependency-free checks in `test/` (render contract, CSS class coverage, display metadata).
